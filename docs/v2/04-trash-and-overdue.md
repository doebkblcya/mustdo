# 垃圾桶与逾期待办

## 目标

为主动删除和近期逾期的待办提供统一处理页面，使用户在七天窗口内可以恢复或重新安排任务。

## 页面入口

- 在待办页顶部栏加入垃圾桶图标。
- 存在已删除或已逾期内容时，图标显示圆点或数量提示。
- 点击图标进入垃圾桶页面。
- 页面顶部显示说明：“已删除和逾期事项最多保留 7 天”。

## 页面结构

垃圾桶页面包含两个切换视图：

- 已删除；
- 已逾期。

每个视图显示当前数量，并按相关时间倒序排列。

## 已删除

已删除视图查询条件为 `deleted_at IS NOT NULL`。

每条记录显示：

- 待办内容；
- 原截止日期和时间；
- 删除时间；
- 恢复入口；
- 永久删除入口。

恢复规则：

- 原截止日期为今天或未来日期时，恢复到原日期；
- 原截止日期早于今天时，恢复到今天；
- 保留原内容、具体时间、完成状态和置顶状态；
- 提醒状态保持关闭；
- 恢复后从已删除视图移除。

## 已逾期

已逾期视图查询条件为：

```sql
deleted_at IS NULL
AND status = 'pending'
AND due_date < today
```

每条记录显示：

- 待办内容；
- 原截止日期和时间；
- 已逾期天数；
- 移到今天入口；
- 编辑、完成和删除入口。

移到今天后：

- `due_date` 更新为今天；
- 保留原 `due_time`；
- 清除提醒状态；
- 任务回到今天列表。

主动删除后，任务进入已删除视图并开始计算七天保留时间。

## API

```http
GET    /api/trash?type=deleted
GET    /api/trash?type=overdue
POST   /api/todos/{todo_id}/restore
POST   /api/todos/{todo_id}/move-to-today
DELETE /api/trash/{todo_id}/permanent
```

列表接口可返回数量摘要，用于顶部垃圾桶图标提示：

```json
{
  "deleted_count": 2,
  "overdue_count": 3,
  "items": []
}
```

## 七天窗口

- 用户删除的事项从 `deleted_at` 开始保留七天。
- 未完成事项从 `due_date` 过期后保留七天。
- 每日清理脚本永久移除超过保留窗口的数据。
- 当日备份在清理脚本运行前完成，清理目标会进入当日运维备份。

## 验收标准

- 垃圾桶图标可以进入已删除和已逾期页面。
- 图标可以提示当前存在待处理内容。
- 删除七天内的待办可以恢复。
- 恢复时可以根据原日期决定回到原日期或今天。
- 逾期待办可以移到今天、编辑、完成或删除。
- 超过七天保留窗口的记录会被每日脚本永久清理。
- 所有查询和操作均按当前用户隔离。
