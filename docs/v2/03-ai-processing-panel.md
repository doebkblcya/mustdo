# ASR 与 AI 统一处理面板

## 目标

使用同一个轻量面板展示语音识别、文本确认、AI 解析和保存过程，让用户清楚看到系统正在处理什么以及最终创建了什么。

## 展示形态

- 使用页面内浮层或底部面板。
- 面板高度随当前步骤和结果数量自适应。
- 已完成步骤收起为摘要，当前步骤保持展开。
- 多条解析结果出现时允许面板向上扩展和内部滚动。
- 文字输入和语音输入复用同一个组件。

## 处理步骤

### 语音输入

```text
上传录音 → ASR 识别 → 展示转写 → AI 解析 → 展示结构化待办 → 保存
```

### 文字输入

```text
展示输入文本 → AI 解析 → 展示结构化待办 → 保存
```

建议视觉状态：

```text
✓ 语音识别
  明天下午三点买菜，周五交房租

✓ AI 整理
  明天 15:00 · 买菜
  周五        · 交房租

○ 正在保存
```

## 两种添加模式

设置页提供两种模式，并记住用户选择。

### 自动添加

- 默认使用自动添加。
- 各处理步骤连续执行。
- 面板实时显示识别文本、解析状态和结构化结果。
- 保存成功后展示实际新增的每条待办。
- 结果停留约两秒，并提供编辑和撤销入口。

### 添加前确认

- ASR 与 AI 解析连续执行。
- 解析完成后停留在结构化结果阶段。
- 用户确认后统一保存。

审核能力包括：

- 编辑转写或输入原文；
- 使用修改后的原文重新解析；
- 编辑单条待办的内容、日期和时间；
- 删除某条解析结果；
- 确认并添加剩余待办。

## 状态机

面板状态建议统一为：

- `uploading`：上传录音；
- `transcribing`：语音识别；
- `parsing`：AI 解析；
- `reviewing`：等待用户确认；
- `saving`：保存待办；
- `done`：保存成功；
- `error`：当前步骤失败。

每个状态保留已经完成的步骤数据，使错误恢复可以从当前阶段继续。

## 错误恢复

- 上传失败：保留录音文件并提供重新上传。
- ASR 失败：提供重试和重新录音。
- AI 解析失败：保留转写文本并提供重新解析。
- 保存失败：保留结构化结果并提供重新保存。
- 关闭存在待确认结果的面板时，弹出放弃确认。

## 撤销

自动添加成功后返回本次创建的待办 ID 集合。用户点击撤销时，后端以一次操作删除本批待办，并刷新当前列表。

```http
POST /api/todos/batch-delete

{
  "todo_ids": [12, 13]
}
```

## 验收标准

- 语音和文字使用同一套处理面板。
- 用户可以看见完整转写文本和结构化结果。
- 自动添加过程连续执行并显示中间步骤。
- 添加前确认会在保存前等待用户操作。
- 修改原文后可以重新触发 AI 解析。
- 任一步骤失败后已有结果得到保留。
- 自动添加完成后可以编辑或撤销本次结果。
