# 今天与明天的 AI 动态整理

## 目标

用户可以让 AI 根据当前事项之间的语义和场景关系动态生成分组，并随时切回原有的时间排序视图。

## 使用范围

- 今天页面支持 AI 整理。
- 明天页面支持 AI 整理。
- 每个日期独立生成并缓存整理结果。

## 页面交互

列表顶部提供两种显示方式：

```text
[ 默认 ] [ AI 整理 ]
```

默认视图保持现有排序。首次切换到 AI 整理时：

1. 收集当前页面可见的未完成事项；
2. 显示“AI 正在整理当前事项”；
3. 请求后端生成动态分组；
4. 按 AI 返回的组名展示任务；
5. 用户可以随时切回默认视图。

示例：

```text
工作
  写周报
  回复客户

采购
  买牛奶
  买猫粮

个人
  晚上跑步
```

## AI 输入与输出

请求携带当前视图和待办最小信息：

```json
{
  "view": "today",
  "items": [
    {"id": 12, "content": "写周报", "due_time": "17:00"},
    {"id": 15, "content": "回复客户", "due_time": null},
    {"id": 18, "content": "买牛奶", "due_time": "19:00"}
  ]
}
```

响应只描述视图分组：

```json
{
  "groups": [
    {"name": "工作", "todo_ids": [12, 15]},
    {"name": "采购", "todo_ids": [18]}
  ]
}
```

## 整理规则

- 根据当前事项的语义、场景、地点或共同目标生成组名。
- 组名保持简短，建议 2 至 6 个汉字。
- 每条待办恰好出现在一个分组中。
- 分组使用请求中存在的待办 ID。
- 事项关系较弱时使用“其他”承接。
- 最多生成 6 个分组。
- 分组内沿用原有的置顶、时间和 ID 排序。

后端校验返回的 ID 集合。缺失的待办补入“其他”，重复 ID 保留第一次出现的位置，请求之外的 ID 直接丢弃。

## 缓存策略

整理结果作为前端视图缓存。缓存键由以下内容生成：

- 当前视图日期；
- 待办 ID；
- 内容；
- 时间；
- 置顶和完成状态。

任务集合保持一致时直接复用缓存。新增、编辑、完成、删除、置顶或移动任务后，缓存键自然变化并在下次进入 AI 整理时重新生成。

## API

```http
POST /api/todos/organize
```

后端校验所有待办均属于当前用户，并记录整理耗时、事项数量和分组数量。

## 验收标准

- 今天和明天可以独立切换默认视图与 AI 整理视图。
- AI 可以根据当前事项动态生成易懂的组名。
- 每条待办在整理结果中出现一次。
- 切回默认视图后恢复原有排序。
- 任务变化后会生成新的整理结果。
- 任务未变化时可以复用本地缓存。
- AI 整理不会修改待办本身的数据。
