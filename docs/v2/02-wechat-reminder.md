# 微信待办提醒

## 目标

用户可以为单条待办主动设置一次微信提醒，在指定时间通过小程序订阅消息收到通知，并从消息返回对应待办。

## 基础规则

- 提醒默认关闭。
- 提醒入口显示在未完成待办的操作区域。
- 待办必须具有明确的 `due_time` 才能设置提醒。
- 缺少具体时间时，点击提醒入口会提示“请先设置明确时间”，并打开待办编辑面板。
- 默认提醒时间为待办时间前 30 分钟。
- 提醒时间必须晚于当前时间。
- 每条待办同时保留一个有效提醒。

## 设置面板

提醒采用轻量面板，展示任务内容、截止时间和提醒选项：

- 准时提醒；
- 提前 10 分钟；
- 提前 30 分钟；
- 提前 1 小时；
- 自定义日期和时间。

打开面板时优先选中“提前 30 分钟”。当该时间已经过去时，依次选择仍然有效的最近选项。所有预设时间均已过去时，引导用户选择自定义时间。

## 授权与创建流程

1. 用户选择提醒时间并点击确认。
2. 小程序调用 `wx.requestSubscribeMessage` 请求一次性订阅授权。
3. 用户接受后，小程序向后端提交 `todo_id` 和 `remind_at`。
4. 后端校验待办归属、状态、具体时间及提醒时间。
5. 后端创建待发送提醒，待办显示提醒已开启状态。
6. 调度器到点调用微信订阅消息发送接口。
7. 消息携带待办详情页或待办列表定位参数。

## 状态模型

提醒记录采用独立表管理异步发送过程：

```sql
todo_reminders (
    id INTEGER PRIMARY KEY,
    todo_id INTEGER NOT NULL UNIQUE,
    user_id INTEGER NOT NULL,
    remind_at TEXT NOT NULL,
    status TEXT NOT NULL,
    created_at TEXT NOT NULL,
    sent_at TEXT,
    updated_at TEXT NOT NULL
)
```

`status` 包含：

- `pending`：等待发送；
- `sent`：微信接口已接受发送请求；
- `failed`：发送失败；
- `cancelled`：因任务状态变化而取消。

## 调度与发送

- FastAPI 启动后创建轻量后台调度任务。
- 调度任务按固定间隔查询 `status=pending AND remind_at<=now` 的记录。
- 当前部署保持单 worker，确保同一提醒只由一个调度实例处理。
- 微信 access token 在内存中按有效期缓存。
- 发送请求包含待办内容、截止时间和小程序跳转路径。
- 发送结果写回提醒状态并记录日志。
- 服务重启后继续扫描所有到期的 `pending` 提醒。

## 状态联动

以下操作会取消有效提醒：

- 完成待办；
- 删除待办；
- 修改待办日期或具体时间；
- 一键移到明天。

恢复已删除待办后，用户可以重新设置提醒。

## 后端接口

```http
PUT /api/todos/{todo_id}/reminder
DELETE /api/todos/{todo_id}/reminder
```

创建或更新提醒：

```json
{
  "remind_at": "2026-08-25T14:30:00+08:00"
}
```

待办响应增加提醒摘要：

```json
{
  "reminder": {
    "remind_at": "2026-08-25T14:30:00+08:00",
    "status": "pending"
  }
}
```

## 验收标准

- 缺少具体时间的待办会引导用户先补充时间。
- 用户接受微信授权后可以成功创建提醒。
- 到达提醒时间后微信收到一条订阅消息。
- 点击消息可以进入小程序并定位对应待办。
- 完成、删除、改期和移到明天会取消原提醒。
- 服务重启后待发送提醒仍能继续执行。
- 微信发送失败会保留可诊断状态和日志。
